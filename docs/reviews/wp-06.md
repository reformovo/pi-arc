# WP-06 评审记录：Run lifecycle 与 Action controller

> 本文是实现评审材料，不是新的实现契约。WP-06 已通过用户审阅；WP-07 至 WP-10 保持 `blocked`。

## 范围与边界

- `src/application/run-controller.ts` 只依赖领域规则、canonical JSON 与注入的 artifact、Environment、Visual、digest、clock ports；不 import filesystem、Python transport、Pi 或模型 SDK。
- `ArtifactStore` 增加只读 `readDomain`/`readTerminal` 恢复入口。读取 domain 时校验完整 hash chain；损坏的 terminal 不会被当成“尚无 terminal”。
- 初始 Observation 与全部 Frame 先写入 artifact，再写 `run.binding` 与 Turn 0；Action 在 Turn 0 确认后才可进入 Environment。
- 每个 Action 使用唯一 `actionId`、invocation ID、同实例 ID 和 base Turn/Observation digest。intent 先于 Environment submission；完整 receipt/全部 Raw Frame/Visual reference 先于 Turn commit。只有 Turn commit 推进当前 Turn。
- 同一时间至多一个 pending Action。RESET 仅在 GAME_OVER 后可用，`retry_state` 与新 Attempt/`boundaryPending` 写在同一 Turn commit；GUIDE/WORKING 物化和 boundary delivery 属于 WP-07。
- 不接入 Pi settlement、模型工具、CLI/SDK、真实模型或真实游戏；本包使用离线 fake Environment 和现有 artifact adapter 测试。

## effect / crash matrix

| 故障侧 | Evidence 与恢复动作 | 验证 | 结果 |
| --- | --- | --- | --- |
| intent 前拒绝或中断 | 无 Action intent、无 Environment 提交、Turn 不变；拒绝写 `tool.rejection` | `T-EFFECT-001` | 通过 |
| intent 已持久、同实例证明未接受 | 查询 `actionId` 与 base anchor；只做一次首次提交，不从 Action log 重建 | `T-EFFECT-002` | 通过 |
| Environment 已接受但只有 pending，或原实例不可查询 | 不重发；唯一终止为 `unknown_action_outcome` | `T-UNKNOWN-001`、`T-EFFECT-006` | 通过 |
| complete receipt 已存在、Turn commit 前 | 校验 identity/digest 和全部 Frame；本地持久 receipt 可直接补 commit，不再依赖 sidecar | `T-EFFECT-003` | 通过 |
| Turn commit 已持久、调用者未收到结果 | 从 ledger 读取既有 Turn，同实例 anchor 校验；Environment submit 次数不增加 | `T-EFFECT-004` | 通过 |
| 无 pending Action 时 Environment 丢失 | 不重放 Action；以已知 `environment_lost` 终止 | `T-EFFECT-005` | 通过 |
| intent 写入后失去 storage acknowledgement | 查 ledger 确认 intent 是否已发布；不放行第二 Action，恢复时查询原实例 | storage fault test | 通过 |
| complete receipt 后本地 Frame 发布失败 | 结果仍可由同实例 receipt 确认；关闭 admission，storage 恢复后补写，不误报 Unknown Outcome | frame fault test | 通过 |
| WIN Turn commit 后、terminal intent 前崩溃 | 不恢复 Environment，依据已提交权威 WIN 补写唯一 terminal | WIN crash test | 通过 |

## 生命周期与终止分类

| 场景 | Turn/Attempt/Run 结果 | 验证 |
| --- | --- | --- |
| 初始 Observation | Turn 0、Level 1、Attempt 1；不是 Action | `T-RUN-001` |
| 普通 Action | 每个 complete receipt 只提交一个新 Turn | `T-EFFECT-003/004` |
| GAME_OVER | 当前 Attempt 结束；Run 保持 active；仅 RESET 可继续 | `T-LIFECYCLE-001` |
| RESET | 新 Turn、同 Level 新 Attempt，`retry_state` 与 boundary flag 同 commit | `T-LIFECYCLE-001` |
| 中间 Level 完成 | 同 Run/Game，新的 Level/Attempt 从权威 Observation 开始 | `T-LIFECYCLE-002` |
| 权威 WIN | `win/WIN`，写唯一 terminal，禁止新 Action；不能由调用者伪造 | `T-LIFECYCLE-002`、WIN crash test |
| 用户取消、无 pending | `non_success/cancelled`，最后 Turn 不变 | `T-CANCEL-001` |
| 用户取消、有可查询 complete receipt | 先完成 Turn commit，再以 `non_success/cancelled` 终止 | `T-CANCEL-002` 竞态测试 |
| 用户取消、pending 无法确认 | `unknown_outcome/unknown_action_outcome` 优先于 cancelled | `T-CANCEL-002` 竞态测试 |
| 原实例丢失、无 pending | `non_success/environment_lost`，不重建 Environment | `T-EFFECT-005` |
| 模型已知失败等 | `model_failure`、`model_no_progress` 等保持 `non_success`；`evidence_corrupt`、`controller_failure` 保持 `audit_failure` | terminal class test |
| terminal 后迟到 receipt | 只追加 `post_terminal.evidence`，不改写终止原因或 Turn | late result test |
