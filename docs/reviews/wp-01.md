# WP-01 评审记录：项目骨架与质量门禁

> 本文是实现评审材料，不是新的实现契约。WP-01 已被用户接受；WP-02 至 WP-10 继续保持 `blocked`。

## 范围结论

本包只实现项目骨架、精确依赖与 lockfile、质量配置、只读门禁、CI 和 meta-fixture。没有实现 ARC、Environment、controller、模型工具、CLI/SDK、Python sidecar wire 或 Pi runtime 行为；没有获取 Game 数据，也没有从旧项目复制源码、fixture 或资产。

VISTA 与 Pi 工作树仍干净。`memo-arc`、`memo`、`pi-memo` 仍保持第 0 轮记录的“仓库无 commit、项目文件为 untracked”状态；`memo-docs` 保持既有用户 dirty 状态。本包没有写入这些工作树。

## 依赖与供应链取舍

- `@earendil-works/pi-agent-core` 与 `@earendil-works/pi-ai` 固定为 0.86.0；Python ARC 依赖与全部质量工具按规范精确固定。
- Vitest 4.1.9 的 peer 解析需要 Vite。为避免 peer 由安装器浮动，增加 direct dev pin `vite` 8.0.16；该版本来自当前 Pi lockfile，不引入业务 runtime surface。
- npm 10.9.8 在首次执行 `npm install --package-lock-only` 时触发 Arborist optional-peer 崩溃；只在生成 lockfile 时使用过 `--legacy-peer-deps` 绕过该 npm bug。最终规范命令 `npm ci --ignore-scripts --no-audit --no-fund` 已在不带 legacy 选项时成功。
- lockfile 中声明 lifecycle script 的包固定为 `@google/genai`、`esbuild`、`fsevents` 和 `protobufjs`。CI 一律使用 `--ignore-scripts`；依赖门禁把这四项作为“已审阅但不执行”的精确集合，新增或删除都会失败。
