# WP-03 评审记录：Artifact ledger 与独立审计

> 本文是实现评审材料，不是新的实现契约。WP-03 已被用户接受；WP-04 至 WP-10 继续保持 `blocked`。

## 范围结论

本包实现了 artifact root 的 durable boundary、append-only domain ledger、runtime JSONL、Raw Frame、Visual reference index、knowledge snapshot index、write-once terminal、迟到 Evidence 和只读 audit/rebuild。没有实现 Game resolver、Environment、controller、sidecar、Pi runtime、CLI 或 SDK。

所有测试使用确定性 fake records 和临时目录；没有下载 Game 数据，也没有读取旧项目、VISTA 或真实 provider。

## 交付内容

- `src/adapters/artifact-store.ts`：`ArtifactStore`、`ArtifactIo` 注入边界、atomic publish、write-once 与 audit reader。
- `manifest.json`、`domain.jsonl`、`runtime.jsonl`、`frames/tNNNNNN/fNNNNNN.json`、`visuals/index.jsonl`、`knowledge/index.jsonl`、`terminal.json` 和 `audit.json` 稳定入口。
- domain record 使用 `sequence`、`previousDigest`、`digest` 形成 canonical JSON SHA-256 链；第一条记录锚定 64 个零 digest。
- terminal 使用同内容幂等、不同内容拒绝的 write-once 语义；terminal 后的 `post_terminal.evidence` 追加不会改写终止记录，也不会让 audit 错误地把 terminal head 判为不一致。
- Raw Frame 在落盘前校验原始 `width × height`、整数像素范围和 content digest；Visual 只保存来源引用，1024×1024 派生 Visual 仍属于后续视觉包。
- atomic publish 使用 `.partial` 临时文件和 rename；audit 会发现残留 partial write。`ArtifactIo` 可注入存储故障以测试 partial-write detection。
- `rebuildAudit()` 从公开入口重建 `audit.json`；只读 `audit()` 不写文件。审计发现 archive corruption、ledger hash-chain 断裂、Raw Frame 损坏、runtime/index 损坏、terminal 缺失或 terminal ledger mismatch。

## 已知边界

1. Visual 实际 PNG 生成与 1024×1024 映射仍属于 WP-04；本包只记录 Visual 到 Raw Frame 的可审计引用。
2. audit 只验证 artifact 结构、链和证据完整性，不判断 Environment 是否真的完成 Action；这需要后续 controller/sidecar 契约。
3. ledger 的物理存储采用整文件 atomic rewrite，尚未引入并发 controller 或 sidecar；WP-06/WP-05 才会补充生命周期与进程故障语义。

## 本轮评审修订

用户指出首版实现缺少文件头与行内注释，并进一步要求说明性注释使用中文。复核 Pi 的开发模式后，WP-03 补齐了中文的非平凡模块职责/边界说明、导出契约 JSDoc/docstring，以及 hash chain、write-once、atomic publish、terminal anchor、跨语言 canonical JSON 和 fault injection 等关键原因注释；Pi/VISTA 标识符保留英文原名，也没有为显然语法增加机械注释。

该评审规则已固化为 accepted [`ADR-0004`](../adr/0004-semantic-comments.md)。后续 work package 必须在评审中检查语义注释，但不设置注释数量或覆盖率门禁。
