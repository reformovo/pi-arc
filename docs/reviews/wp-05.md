# WP-05 评审记录：Python Environment sidecar

> 本文是实现评审材料，不是新的实现契约。WP-05 已通过用户审阅；WP-06 已获授权，WP-07 至 WP-10 继续保持 `blocked`。

## 范围结论

本包实现了 TypeScript ↔ Python 的 versioned JSONL envelope、真实本地 Python process、Environment instance identity、串行请求、Action receipt、同 `actionId` 去重、参数冲突拒绝、anchor 校验、disconnect/process cleanup 和 crash 前 pending durable cache。

本包没有实现 Run controller、Turn commit、Pi runtime、模型调用、CLI 或 SDK。receipt 仍是 Environment authority 的证据；它不会被 sidecar client 自动提升为 ARC Turn commit。

## 实现边界

- `src/adapters/sidecar-client.ts` 只负责子进程启动、secret/proxy 环境清理、network sentinel、JSONL request/response matching、严格串行和 process cleanup。
- `python/pi_arc_sidecar/sidecar.py` 负责只读 Environment root 校验、官方 `arc-agi` offline wrapper 或 deterministic fixture 的加载、唯一 `environmentInstanceId`、Action 状态机、Raw Frame 校验、receipt digest 和原子 cache 发布。
- sidecar 只收到 `environment/` 子目录与独立 `cacheRoot`；启动环境移除 provider/OAuth secret、proxy、`ARTIFACT_ROOT` 和 `PI_SESSION`，并在 `PI_ARC_BLOCK_NETWORK=1` 下阻断 Python socket。
- `open` 的 wire payload 必须再次匹配进程启动时的 `gameId`、`sourceLocator`、`treeDigest` 与 `seed`，避免 controller 和 Environment 绑定到不同的 Game cache。
- `ACTION6` 只接受已映射的 `0..63` 坐标；RESET 拒绝 `retry_state`；sidecar 不接收 1024×1024 模型坐标或模型笔记。
- complete receipt 直接包含 base anchor、完整 Observation、全部 Raw Frames、结果状态和 receipt digest；重复相同参数只返回既有 receipt，不再次调用 Environment。

## 已知边界

1. crash 后新 Python 进程不会继承旧 `environmentInstanceId`；它会拒绝已有 cache，controller 必须按规范将 pending Action 分类为 Environment lost 或 Unknown Outcome，不能自动重放。
2. 真实官方 Game 的调用通过 `arc-agi==0.9.9` 的 `OperationMode.OFFLINE` wrapper；required tests 使用 deterministic fixture，不访问 catalog 或真实下载。
3. sidecar 不负责将 receipt 写入 Run `domain.jsonl`，也不实现 receipt → Turn commit 的恢复逻辑；这些属于 WP-06。
