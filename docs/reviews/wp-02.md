# WP-02 评审记录：版本化 contract 与共享 fixtures

> 本文是实现评审材料，不是新的实现契约。WP-02 已被用户接受；WP-03 至 WP-10 继续保持 `blocked`。

## 范围结论

本包只实现公共 JSON contract 的 source、生成的 JSON Schema、canonical JSON/digest primitives、双端 schema validator 和共享 valid/invalid corpus。没有实现 artifact ledger、Environment、controller、sidecar transport、Pi runtime、CLI 或 SDK 行为。

没有下载 Game 数据，也没有复制旧项目或 VISTA 的源码、fixture、运行材料。所有 fixture 都是小型脱敏记录，不含真实 provider transcript、credential 或 Game 文件。

## 单一 source of truth 与生成布局

`schemas/source.json` 是唯一 schema source，当前生成 13 个 v1 schema：

- `pi-arc.cli-event.v1`
- `pi-arc.run-manifest.v1`
- `pi-arc.domain-record.v1`
- `pi-arc.runtime-record.v1`
- `pi-arc.raw-frame.v1`
- `pi-arc.terminal.v1`
- `pi-arc.audit.v1`
- `pi-arc.sidecar-request.v1`（JSON `schema` 为 `pi-arc.sidecar.v1`）
- `pi-arc.sidecar-response.v1`（JSON `schema` 为 `pi-arc.sidecar.v1`）
- `pi-arc.tool-call.v1`
- `pi-arc.tool-result.v1`
- `pi-arc.run-result.v1`
- `pi-arc.audit-result.v1`

生成结果位于 `generated/schemas/`，由 `npm run generate:schemas` 显式写入，同时刷新 `generated-manifest.json`。required checks 不运行生成或自动修复；`check-generated` 在内存中重建期望文本，逐文件比较 source、生成文件和 SHA-256 manifest，发现 drift 立即失败。

TypeScript 的 `src/protocol/canonical-json.ts` 只负责纯 canonical bytes；Node SHA-256 适配器位于 `src/adapters/sha256.ts`，避免 protocol 层依赖 Node I/O。Python sidecar 提供对应的 `canonical_json`、`canonical_json_bytes` 和 `canonical_json_digest`。两端都按 Unicode code point 排序对象 key、保持数组顺序、拒绝非安全整数，并以单个 `\n` 结束 canonical bytes。

## Fixture matrix

| Fixture 集 | 覆盖 |
| --- | --- |
| `canonical-vectors.json` | Unicode/emoji、key order、嵌套对象/数组、空结构、`±(2^53-1)` 安全整数、固定 canonical bytes 和 SHA-256 |
| `schema-corpus.json` valid | CLI event、Run manifest、domain/runtime record、Raw Frame、terminal/audit、sidecar request/response、tool call/result、Run/Audit result |
| `schema-corpus.json` invalid | 未知字段、未知 enum、v2 major mismatch、超出 JavaScript safe integer、坐标常量错误、digest pattern 错误、未知 sidecar type |
| TS/Python contract tests | 同一 fixture path、同一生成 schema、同一 valid/invalid 结论 |
| TS/Python unit tests | canonical rejection edge、schema required/additional/type/min/max/pattern/array 分支 |

validator 只实现本 source 使用的严格 JSON Schema 子集（`type`、`const`、`enum`、`required`、`properties`、`additionalProperties`、`items`、长度/整数边界和 pattern）；它不是新的通用 JSON Schema runtime，也不改变规范的公开字段。

评审确认当前 schema 是后续 work package 可逐步收紧的 v1 scaffolding：`data`、`payload`、`args` 和 `result` 暂时允许开放对象。各 owning package 实现具体行为时，必须同步更新 source、生成文件、共享 corpus、双端 contract tests 和 manifest digest。Raw Frame 已按评审修正为保存正整数原始宽高；只有派生 Visual 固定为 1024×1024。

## 剩余风险与停止点

1. schema validator 是针对当前 source 子集的最小 strict validator，不承诺成为通用 JSON Schema 实现；新增 schema keyword 必须先扩展双端 validator 和 corpus。
2. 具体 artifact ledger、receipt/action 三段协议和 CLI/SDK 生命周期仍属于后续 work package，本包只固定它们的 JSON record shape。
3. required checks 尚未在 GitHub-hosted Ubuntu 上执行；这是 WP-10 的 CI/branch protection 证据，不阻塞本包本地验收。

WP-02 已通过用户审阅并在此停止；WP-03 仍需另行授权。
