## 历史阻断问题：官方 SDK `Arcade.make()` 会执行下载的 Game code

以下分析针对原基线 `pi-arc-v1-2026-09-22`；用户随后已接受 ADR-0005，解除这一设计冲突，不代表当前草案已通过实现验收。

规范第 15.6 节同时要求通过 `arc-agi==0.9.9` 官方 SDK 下载 Game，并要求下载的 Environment code **只能在 Python Environment sidecar 中加载**。实际 SDK 0.9.9 的 `Arcade.make()` 在 NORMAL 模式调用 `_download_game()`；后者写入 metadata/source 后立即调用 `_create_wrapper()`，而 `LocalEnvironmentWrapper` 初始化会加载 Game class。公开 `Arcade` 没有单独下载文件而不构造 wrapper 的方法。

当前草案的 `python/pi_arc_sidecar/catalog_fetch.py` 调用 `Arcade.make()`，在独立 catalog 获取进程中执行了 Game code。该进程还必须持有下载所需的 ARC 凭据。进程分离不足以满足“Game code 只在受限 Environment sidecar 加载”和“Game code 不获得凭据”两项要求。因此该适配器**不能作为已接受实现**；离线测试不会触发真实 SDK 分支，无法消除这一矛盾。

另外，当前草案把 `ARC_API_KEY` 设为 cache miss 的必要条件，而 SDK NORMAL 模式在缺少 key 时可尝试匿名 public catalog。这个额外前置条件也需在设计中明确是否允许。

## 当时提出的设计选择

1. 推荐：将第 15.6 节的“通过官方 SDK 下载”收窄为“使用官方 public catalog 的 metadata/source HTTP 接口获取”，在无 Game code 执行的下载进程中校验精确版本和来源；Environment code 仍只在离线 sidecar 加载。需明确匿名访问与显式 ARC key 的规则，并重新评审规范/handoff。
2. 保留 `Arcade.make()`：必须显式改变 Game code 隔离/凭据边界，接受其在下载进程内被加载；这削弱现有安全约束，不建议。
3. 等待官方 SDK 提供不加载 Game code 的公开下载 API，再继续 WP-09。

原停止条件是选择并更新 accepted 规范；该设计条件已通过下述用户决策解除，后续实现与门禁通过后，用户已审核通过 WP-09 并授权提交。WP-10 不随本包验收自动开始。

## 已确认的决策与本次收尾

用户明确选择“信任官方 game 并接受获取阶段接触 ARC 凭据”。[ADR-0005](../adr/0005-official-sdk-acquisition-trust.md) 与规范第 15.6 节现允许独立官方 SDK 获取进程临时加载 Game code，正式 Run 仍从已验证缓存启动无凭据的 offline Environment sidecar。handoff 已更新至 `pi-arc-v1-adr-0005`；不再改走自建 HTTP 获取路径。

上述剩余实现与离线验证已完成：

1. 获取与运行子进程采用环境白名单，不继承模型/provider/OAuth 凭据、HOME、proxy、Pi 配置或 artifact 路径。获取进程只额外传入显式 ARC key。实际子进程探针覆盖有 key/无 key 两条路径。
2. SDK import 会读取 cwd 的 `.env`/`.env.example`；获取在空临时 cwd 导入 SDK，正式 sidecar 在独立 receipt 临时目录启动。SDK 专用 logger 禁用，避免匿名 key 被 SDK 日志输出。
3. 删除 cache miss 强制 key；未提供 key 时使用 SDK 公开 NORMAL 匿名路径（SDK 会获取匿名 key），显式 key 失败不切换匿名或重试。Python fake SDK 测试覆盖初始化失败、make 失败、版本不匹配与日志/临时目录清理，无私有 API 或 operation mode 突变。
4. 端到端 fake SDK 返回获取阶段伪 WIN，而正式 Run 从缓存重新初始化为 NOT_FINISHED，再由一个权威 Action 达到 WIN。Game fixture 在加载时断言无 ARC key/未知 provider 凭据。receipt 目录不包含 artifact 路径，并在 sidecar 关闭后清理；构造 sidecar 失败也清理目录并返回 startup_failed。
5. 修复 Game ID 校验比规范更窄的问题；resolver、SDK、CLI 和生成 schema 接受规范的完整字母数字版本 suffix，仍要求 catalog 精确匹配，不猜测版本或 fallback。
6. CLI 在调用 host 前验证 budget 上界与 Game ID 格式；损坏的 resume archive、controller failure、event archive 损坏均返回 30，并保留最终 JSONL。已有 terminal 的 resume 保持只读；CLI 必要时仅补充本次输出，不写入 archive。
7. 同步 package-lock 的 CLI bin 入口，并排除 `.delta` 下的独立工作树，避免门禁误扫描嵌套 Biome 配置与历史文档。
