# 第 0 轮评审记录：事实基线

> 状态：已通过（2026-09-20）。本文是评审记录，不是实现契约。

## 本轮完成项

- 核对 Pi、VISTA、`memo-arc`、`memo`、`pi-memo` 和 `memo-docs` 的 Git 与版本状态。
- 为 Pi/VISTA 关键来源和冻结 ARC 游戏记录 SHA-256。
- 提炼 Pi 的唯一规范、gated 能力、actionable handoff、小型 work package 和审批停点模式。
- 区分当前实现事实、历史文档、设计证据和尚未实现的提案。
- 建立第一版需求与证据追踪表。
- 建立唯一规范骨架，但没有写入内部设计或公共接口细节。
- 确认本轮没有修改来源项目、迁移资产、创建工具配置或删除旧项目。

## 主要发现

1. Pi 已更新到 `0.86.0`，稳定 AgentHarness v4 已具备 durable session、lane watch、工具 replay/memo 和 JSONL repository；旧方案不能继续以 coding-agent `0.85.1` 为运行时事实。
2. Pico3 核心实现较完整，但仍位于 experimental export，仓库内 `micro` 不能作为已发布公共适配层。
3. VISTA 的参考行为已提交为 `63c8843822cb371bb52a59f0cee18c4020f2494b`（`test: codex`），工作树干净；关键文件哈希与第 0 轮最初采集结果一致。
4. 三个待退役项目均无 commit。删除它们不仅是代码清理，也是不可逆的数据删除。
5. `memo-arc` 中 `ls20-9607627b` 的两个游戏文件与 manifest 哈希一致，但它们只作为旧项目事实证据，不再是计划迁移的资产；新项目将统一重新拉取所需 game 数据集。
6. `pi-arc` 面向模型的显示与工具坐标空间已确认保持 VISTA Codex 路径的 1024×1024；ACTION6 仍映射到 64×64 原始环境网格，不再引入 512×512 中间坐标空间。

## 本轮已解决的设计分歧

| 问题 | 结论 | 后续工作 |
| --- | --- | --- |
| 是否将 VISTA 的 1024×1024 坐标改为 512×512 | 不修改，保持 1024×1024；512×512 只是旧方案遗留假设，不是 Pi 或 ARC 约束 | 第 2 轮将现有 VISTA 坐标语义写成可验收的外部行为契约 |
| 是否把 `memo-arc` 中的冻结游戏文件迁入新项目 | 不迁移；新项目使用统一的数据获取流程重新拉取所需 game 数据集 | 第 2、4 轮明确权威来源、固定版本、缓存和完整性校验 |
| 是否继续把 VISTA dirty working tree 当作参考快照 | 不需要；相关变更已提交为 `63c8843`，后续用 commit 加关键文件哈希定位 | 后续轮次发现 VISTA 漂移时先做影响分析 |

## 尚未解决的问题

| 问题 | 影响 | 处理轮次 |

| `Run`、`Game`、`Attempt`、`Turn` 的边界和中文释义尚未统一 | 影响所有生命周期和计数口径 | 第 1 轮 |
